# Запись экрана кола через покадровые скриншоты

## Задача

Запись экрана во время кола делать не через gst/pipewiresrc (сломан на связке
Ubuntu 26.04 / KWin 6.6 / PipeWire 1.6.2 — см. [[screencast-0byte-pipewiresrc]]),
а покадрово: раз в секунду снимать центральную полосу экрана через KWin
ScreenShot2 (тот же путь, что кнопка «📸 Область»), а кнопкой «🎬 Склеить»
собирать кадры в видео на 1 fps и мукать с аудиодорожками в `combined.mp4`.

## Контекст

- Скриншот уже реализован: `kwin_shot::capture_area(x, y, w, h)` — D-Bus
  `org.kde.KWin.ScreenShot2.CaptureArea`, возвращает `image::RgbaImage`.
- Авторизация ScreenShot2 требует зарегистрированного `.desktop`
  (`X-KDE-DBUS-Restricted-Interfaces=org.kde.KWin.ScreenShot2`), что делает
  `screenshot::ensure_registered()`. Захват работает ТОЛЬКО из процесса
  запущенного виджета (standalone-CLI получает `NoAuthorized`).
- Монитор: логическая геометрия 4096×1728, режим 5120×2160, scale 1.25.
- Кол пишется в `~/.local/share/health-widget/calls/<id>/`: `mic.wav`,
  `zoom.wav` (аудио), сейчас ещё `screen.mkv` (0 байт, gst сломан).
- Кнопка «🎬 Склеить» (`mux.rs`) уже мукает видео+аудио в `combined.mp4`;
  сейчас деградирует в аудио-only, т.к. `screen.mkv` пустой.

## Поведение

### Захват (во время кола)

Новый модуль `src/frames.rs`, `FrameCapture`:
- `start(dir: &Path) -> FrameCapture` — спавнит фоновый поток; создаёт
  `dir/frames/`.
- Поток по расписанию раз в 1 секунду (сон до следующей секундной границы,
  чтобы кадр N ≈ секунда N кола):
  - снимает центральную полосу через `kwin_shot::capture_area(x, 0, w, H)`;
  - сохраняет `dir/frames/{n:06}.jpg` (JPEG качества ~85, `image`-крейт;
    альфа отбрасывается);
  - `n` — счётчик с 1.
- При ошибке захвата (например `NoAuthorized` вне зазора авторизации) — кадр
  пропускается, ошибка логируется через `telemetry::error`, поток продолжает.
- `stop(self)` — атомарный флаг + `join`.

Центральная полоса: цель — ≈2500 выходных пикселей по ширине, полная высота.
ScreenShot2 принимает логические координаты, а возвращает картинку в
устройственных пикселях (scale 1.25), поэтому целевая логическая ширина =
`2500 / scale = 2000`. Область: `x = (W_lg − w_lg) / 2`, `y = 0`, `w = w_lg`,
`h = H_lg`, где `w_lg = min(2000, W_lg)`; `x` и `w` округляются вниз до чётного
(h264 требует чётные стороны выходного кадра).

Логическую геометрию берём один раз при `start`: `kscreen-doctor -j` → у
включённого выхода `currentMode.size` (физика) и `scale`, отсюда
`W_lg = size.width / scale`, `H_lg = size.height / scale`. При неудаче разбора —
фолбэк `4096×1728`. Фактический размер кадра берём из ответа ScreenShot2 (meta
`width`/`height`), на него же полагаемся при сборке — подгонять не нужно, важно
лишь постоянство размера между кадрами (геометрию считаем один раз за кол).

### Разведение (`main.rs`)

- `ActiveCall`: поле `screen: Option<screencast::ScreenRecorder>` заменяется на
  `frames: Option<frames::FrameCapture>`.
- `start_call` вместо `start_screen_recording` заводит `FrameCapture::start`.
- `end_call` — `frames.stop()`.
- `start_screen_recording` удаляется.

### Сборка (кнопка «🎬 Склеить», `mux.rs`)

`glue_dir` для кола, где есть `frames/` с ≥1 кадром:
```
ffmpeg -y -hide_banner -loglevel error \
  -framerate 1 -i frames/%06d.jpg \
  -i mic.wav -i zoom.wav \
  -filter_complex "[1:a][2:a]amix=inputs=2:normalize=0[a]" \
  -map 0:v -map "[a]" -c:v libx264 -pix_fmt yuv420p -c:a aac combined.mp4.part
```
- Видео на 1 fps ⇒ длина видео = число кадров ≈ длина кола ⇒ синхрон с аудио.
- `libx264` (не nvenc — вход JPEG, GPU-энкодер не нужен; надёжнее).
- Матрица аудио как сейчас: оба трека → `amix`; один трек → он; нет аудио и
  есть кадры → видео без звука.
- Нет кадров и есть аудио → аудио-only (текущий фолбэк).
- Успех: `rename` `.part` → `combined.mp4`, затем удалить `frames/`.
- Маркер «склеено» = наличие `combined.mp4` (как сейчас).
- `pending()` дополняется: кандидат — папка с `frames/` (≥1 кадр) ИЛИ с
  аудио, без `combined.mp4`, не активный кол.

## Что удаляется

`src/screencast.rs` целиком (portal ScreenCast + gst pipewiresrc, `died_early`,
захват stdout) и подкоманда `--screencast-test` в `main.rs`, поле
`ActiveCall.screen`, `mod screencast`. Путь подтверждённо не работает на этой
связке и полностью заменяется кадрами. Токен `screencast.token` больше не
используется (файл можно оставить, кодом не трогаем).

## Данные и риски

- Хранение: ~2500×2160 JPEG ≈ 0.3–0.8 МБ/кадр → ~0.5–1.4 ГБ на 30-мин кол,
  **временно** — `frames/` удаляется после успешной сборки.
- Виджет может попасть в центральную полосу (обычно в углу; на ScreenShot2
  `excludeFromCapture` не влияет) — некритично.
- Захват ~50–150 мс/кадр (пиксельный `build_rgba` по ~5.4 Мпикс) в фоновом
  потоке; на 1 fps не мешает UI.
- Дрейф синхрона: при захвате ~100 мс интервал слегка плывёт; на 1 fps и колах
  минут-часов накопление незначимо. Не корректируем.

## Ограничения проекта

Без комментариев в коде; строки UI по-русски; ветка `master`; шеллить готовые
CLI (`ffmpeg`, `kscreen-doctor`), не тянуть Rust-зависимости. `ffmpeg` и
`kscreen-doctor` установлены.

## Тесты

- `frames`: центрирование полосы — чистая функция `band(w_lg, h_lg, target) ->
  (x, y, w, h)` возвращает центрированную, чётную по сторонам область,
  клампится к экрану. Юнит-тест на `tempdir`/значениях.
- `mux`: `pending` включает папку с `frames/` без `combined.mp4` и исключает
  активный кол / уже склеенные / пустые. Юнит-тест на `tempdir`.
- Реальный захват и сборка — вручную из живого виджета (ScreenShot2 требует
  авторизации; внешний ffmpeg в юнит-тестах не гоняем).

## Вне рамок

- Настройка ширины/интервала через UI — константы в коде.
- Пропуск неизменившихся кадров / дедуп — не сейчас.
- Удаление файла `screencast.token`.
