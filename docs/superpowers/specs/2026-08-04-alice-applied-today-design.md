# Алиса: «сколько сегодня откликов»

**Дата:** 2026-08-04
**Статус:** дизайн утверждён, план не написан

## Цель

Спросить у Яндекс.Станции «Алиса, спроси у автопилота сколько сегодня откликов»
и услышать число откликов, сделанных автопилотом за сегодня — суммарно по всем
профилям из `PILOT_PROFILES`.

Не входит в объём: сводки по профилям, ответы HR, количество найденных вакансий,
управление автопилотом голосом. Только цифра.

## Ограничения

- Яндекс.Диалоги требуют публичный бэкенд с ответом за 3 секунды. Домашняя машина
  за NAT напрямую не годится.
- Своего домена и VPS нет; `aws` и `yc` в системе не установлены, `curl` и `jq` есть.
- ПК может быть выключен или спать в момент вопроса — Алиса всё равно должна
  ответить, но не выдавать протухшее число за свежее.
- Данные уже есть: `pilot_summary::Summary.applied_today` и `daily_limit`
  (`src/pilot_summary.rs`), добываются вызовом `<autopilot_bin> summary --profile <key>`.

## Архитектура

Одна публичная Cloud Function в Yandex Cloud с двумя входами, различаемыми по телу POST:

- **пуш от виджета** — `{"token", "applied_today", "daily_limit", "date"}` →
  функция пишет объект `applied.json` в приватный бакет Object Storage;
- **запрос от Диалогов** — есть поля `request`/`session` → функция читает
  `applied.json` и отвечает фразой.

```
виджет (раз в 5 мин)  --curl POST {token,...}-->  Cloud Function  --> Object Storage
Станция --> Диалоги --POST--> Cloud Function  <-- Object Storage --> «Сегодня 14 откликов»
```

Почему пуш идёт через функцию, а не прямо в Object Storage: подпись S3-запросов из
Rust или `curl` дорога в реализации, и статические ключи от бакета пришлось бы
держать на десктопе. При выбранной схеме виджету нужен только `curl` и один токен,
ключи хранилища не покидают облака.

Почему не туннель в виджет (cloudflared): quick-туннель меняет адрес при каждом
рестарте, а именованный требует своего домена в Cloudflare; плюс ПК должен быть
всегда включён.

### Формат объекта `applied.json`

```json
{
  "applied_today": 14,
  "daily_limit": 200,
  "date": "2026-08-04",
  "updated_at": "2026-08-04T12:30:05+03:00"
}
```

`date` — дата по московскому времени на стороне виджета; `updated_at` — момент пуша.

### Правила ответа

Все проверки — относительно текущего московского времени на стороне функции.

| Состояние | Ответ |
|---|---|
| `date` в объекте ≠ сегодня | «Сегодня откликов ещё нет» |
| пуш моложе 30 минут | «Сегодня 14 откликов» |
| пуш старше 30 минут | «Сегодня 14 откликов, данные на 12:30» |
| объекта нет или он не читается | «Не могу получить данные» |

Ответ всегда с `end_session: true` — вопрос одноразовый, диалог не держим. Пустой
запуск («Алиса, запусти автопилот») сразу называет цифру: отдельного приветствия нет.

## Компоненты

### `src/alice.rs` (виджет, Rust, ~120 строк)

Отдельный поток, тик раз в 5 минут:

1. `pilot_summary::fetch` по каждому ключу из `PILOT_PROFILES`;
2. сумма `applied_today` и сумма `daily_limit` по успешно полученным профилям;
3. пуш `curl -m 5 -X POST -H 'Content-Type: application/json' -d @- <url>`, если
   сумма изменилась с прошлой отправки **или** с прошлой отправки прошло больше
   20 минут (heartbeat, чтобы не всплывало «данные на …» на неизменной цифре).

Конфиг — `~/.config/health-widget/alice.json`: `{"url": "...", "token": "..."}`.
Файла нет → поток не стартует, ни ошибок, ни логов. Провалы `curl` пишутся в
`telemetry`, ретраев нет: следующий тик через 5 минут.

Интерфейс наружу: `alice::spawn(cfg) -> Option<JoinHandle>`, вызывается из `main.rs`
рядом с остальными фоновыми потоками. Модуль не знает про UI и не трогает состояние
виджета.

### `cloud/alice/handler.py` (~80 строк) + `requirements.txt`

`boto3` к `https://storage.yandexcloud.net`, статический ключ из переменных окружения
(`ALICE_BUCKET`, `ALICE_PUSH_TOKEN`, `ALICE_SKILL_ID`, ключи доступа).

- Пуш: сравнение токена константным по времени сравнением; несовпадение → 403.
- Запрос Диалогов: `session.skill_id` сверяется с `ALICE_SKILL_ID`; чужой навык,
  постучавшийся на наш URL, ответа не получает. Если `ALICE_SKILL_ID` не задан
  (навык ещё не создан), проверка пропускается.

Формирование фразы — чистая функция от `(объект, «сейчас»)`, чтобы тестировалась
без сети.

### `scripts/alice-deploy.sh`

Идемпотентный деплой на `yc` CLI; если `yc` не найден — ставит его в
`~/yandex-cloud/bin` официальным установщиком. Шаги:

1. бакет Object Storage (приватный);
2. сервисный аккаунт `health-widget-alice`, роль `storage.editor` на бакет;
3. статический ключ доступа (только если ещё не создан);
4. push-токен (генерируется один раз, хранится в `~/.config/health-widget/alice.json`);
5. zip функции, `yc serverless function version create` с env;
6. публичный вызов: `--role functions.functionInvoker --subject all`;
7. запись `url` и `token` в `~/.config/health-widget/alice.json`;
8. печать id функции для Консоли Диалогов.

Повторный прогон = новая версия функции; бакет, аккаунт, ключи и токен переиспользуются.

Отдельный режим `scripts/alice-deploy.sh --skill-id <id>` — дописать `ALICE_SKILL_ID`
в env функции после того, как навык создан.

### Ручные шаги (в README)

1. Создать навык в Консоли Диалогов, имя активации — **автопилот**.
2. Backend = Cloud Function, id из вывода деплой-скрипта.
3. Скопировать skill_id, прогнать `scripts/alice-deploy.sh --skill-id <id>`.
4. Опубликовать навык приватно (доступен только своему аккаунту).

Фраза вызова: «Алиса, спроси у автопилота сколько сегодня откликов».

## Тесты

**Rust (`src/alice.rs`)**
- сборка payload из нескольких `Summary` — суммы складываются, дата в формате `YYYY-MM-DD`;
- правило отправки: цифра изменилась → пуш; не изменилась и прошло 5 минут → тишина;
  не изменилась и прошло 25 минут → пуш;
- ни одного профиля не удалось получить → пуша нет.

**Python (`cloud/alice/handler.py`)**
- дата сегодняшняя, пуш свежий → «Сегодня 14 откликов»;
- дата вчерашняя → «Сегодня откликов ещё нет»;
- пуш старше 30 минут → фраза с «данные на HH:MM»;
- объекта нет → «Не могу получить данные»;
- чужой `skill_id` → отказ;
- плохой push-токен → 403;
- корректный пуш → объект записан.

## Риски

- **Холодный старт функции.** Диалоги ждут 3 секунды. Питон + boto3 стартуют
  за сотни миллисекунд, запас есть, но при первых запросах после долгого простоя
  стоит проверить фактическое время ответа.
- **Публичный URL функции.** Наружу утекает только число откликов; запись защищена
  токеном, чтение Диалогами — сверкой skill_id.
- **Стоимость.** Объём вызовов (десятки пушей в день) укладывается в бесплатный
  тариф Cloud Functions и Object Storage.
